# 教务 JSON 本地导入与 Windows 助手

## 技术路线与边界

MyTimetable 是不同来源的静态 PWA，不能读取学校网站的登录状态，也不能跨站访问学校 DOM 或请求。此次保留 PDF 和 JSON 备份，新增独立的**教务 JSON 适配器**与本地 Chrome / Edge Manifest V3 扩展。

数据路径：你正常登录学校 → 学校页面自行查询 → 助手读取随后返回的同源 JSON → 只保留课程字段 → 手动下载文件 → MyTimetable 预览、修改、去重 → 确认后保存在本机 IndexedDB。

这借鉴了“用户在学校页面完成正常登录后，自己把课程带走”的工作方式，不声称复现其他产品的实现，不使用未确认的学校 API。没有接口地址、自动登录、自动请求、定时同步或企业微信同步按钮。

已有事实仅是用户观察到 JSON 的八个字段；尚无实际匿名响应用于验证学校具体封装与编码。因此：

- 优先支持可确定的字段，嵌套响应可从数组、data、rows、kbList 等容器自动找课程对象。
- `kcmc`、`cdmc`、`jsxm` 映射名称、地点、教师；`xqj=1…7` 或“星期一…星期日”映射星期，两者冲突则待确认。
- `jcs` / `jc` 支持明确的 `1-2`、`第1-2节`、`1,2,5,6` 或数字数组；不连续节次拆成多个安排。`jcs` 与 `jc` 都明确且相互矛盾时待确认。
- **不猜测** `jc=2` 是课时数、开始还是结束，也不擅自解码 `0102` 或单个裸数字 `jcs`。
- `zcd` 支持 `3周,6-19周`、`3-5周(单),6-18周` 等混合表达式，或明确的范围、列表、数字数组。单个裸数字（包括数字字符串）可能是位掩码，不猜测，保留原字段供核对。
- 没有可靠星期、节次、周次的课程不会丢弃，进入“其他／待确认课程”。可在导入前或之后补齐。
- 不从未知字段推断开学日期、作息或学期；可手动填写学期名称。

若未来希望后台同步或自动重放查询，需要学校提供正式、允许第三方使用的接口及授权机制。当前方案不代表校方授权；请遵守学校对本人数据导出的规定。若学校只允许企业微信内部访问，普通浏览器没有已登录的学校页面，本助手不能接管企业微信客户端；需要校方允许的浏览器入口或其他允许的课程导出方式，不能通过复制登录凭据解决。

## Windows：使用本地扩展

1. 登录 GitHub，打开仓库 **Actions → 构建 Windows 浏览器扩展**，选最新的绿色成功运行，在页面底部 **Artifacts → MyTimetable-Windows-Helper** 下载 ZIP。不要下载 Code → Download ZIP。无需运行任何命令。也可从已部署的新版本 MyTimetable 的导入窗口下载扩展 ZIP。
2. 解压 ZIP，找到包含 `manifest.json`、`popup.html`、`capture.js` 的目录。
3. Chrome 打开 `chrome://extensions`，或 Edge 打开 `edge://extensions`。开启“开发者模式”，点击 **加载已解压的扩展程序**，选择上述目录。它不是已上架的商店扩展；不需要收费或后台服务。
4. 在学校允许的普通浏览器入口正常完成企业微信扫码登录，打开**本人**课表。扩展不会帮助或绕过登录。
5. 点击扩展图标，核对显示的当前网站来源，然后点击 **我已登录，开始读取课表**。只授予当前活动标签页的临时权限。
6. 关闭弹出窗口，回到学校页面，选择**完整学期**并点击“查询”或其他会重新请求课表的正常操作。**不要刷新整个页面**：整页刷新会移除读取器，需要重新开始。
7. 再打开扩展，点击“检查课表”。检查课程数量和字段，填写学期名称（选填），点击 **导出课程 JSON 到电脑**。若有多次匹配的响应，只保留最近一次，避免将不同查询范围自动拼在一起。
8. 导出后点击 **停止并清空**。页面刷新、关闭标签页或 10 分钟超时也会清空；关闭扩展弹窗本身不会中断正在进行的本页查询。
9. 在 Windows MyTimetable 选择“教务 JSON → 选择教务 JSON”，预览修改后合并或替换。会检查重复与冲突，且导入前保留一个本机恢复点。

限制：扩展只注入**当前主文档**，不读取过去已经完成的请求；页面提前缓存了 fetch 函数时可能观察不到请求。跨域 iframe、跳转后的页面、学校 CSP 限制、WebSocket、非 JSON/加密响应、浏览器策略禁止开发者扩展时，均可能读不到。不要为此提供 Cookie / Token 或授予所有网站权限；使用下一节的响应正文方式，或学校允许的导出方式。

## 无扩展：导入响应正文

1. 在已经正常登录并打开课表的浏览器按 F12，打开 **网络（Network）**，选择 Fetch/XHR。
2. 通过学校页面正常执行一次学期查询；找到你已确认会返回课程 JSON 的请求。
3. 在 **响应（Response）** 页复制 JSON 正文。不要复制请求头、Cookie、Authorization、cURL 或 HAR 文件，也不要把这些内容发送给开发者。
4. 在 MyTimetable 的“教务 JSON”中展开粘贴区域，将正文粘贴并点击“解析响应正文”；或将纯 JSON 正文保存为 `.json` 文件后选择导入。
5. 解析后只保留八个课程字段；响应中的学生身份、登录信息与其他字段不会进入导入原文或本机课表。即使过滤后仍需视导出课程文件为私人安排，不要公开提交或分享。

## 传到 iPhone

- Windows 导出的 `MyTimetable-school-courses.json` 可通过你选择的文件传输方式传到 iPhone，例如 iCloud Drive、USB 或自己的私密聊天附件。第三方传输工具可能上传文件，由你自行选择；MyTimetable 本身不会上传。
- 在 iPhone Safari 或已安装的 MyTimetable 主屏幕应用中，打开“导入课表 → 教务 JSON → 选择教务 JSON”，从“文件”中选中 JSON，核对学期、周次、节次与地点后确认。
- 如果已经在 Windows MyTimetable 核对完成，也可导出完整 MyTimetable JSON 备份，到 iPhone 使用 **设置 → 从备份恢复**。这是另一个入口，会替换全部课表设置；教务 JSON 入口支持合并并保留本机时间配置。
- 没有云同步，不假定电脑和手机或 Safari 与主屏幕窗口共享存储。请在最终使用的窗口内导入并定期备份。

## GitHub 云端安装包

工作流 `.github/workflows/build-helper.yml` 在分支代码推送、main 的 PR 和手动运行时执行：云端安装依赖 → 全量单元测试 → 应用与扩展构建 → 安装包完整性/权限/资源验证 → 上传解压后即可加载的文件夹。`upload-artifact` 自动生成单层 ZIP，避免二次解压。验证失败不发布产物。运行摘要中也会显示下载入口与安装步骤。

Artifacts 需登录 GitHub 下载，保留 30 天。工作流文件合并到 main 后，可在 Actions 点 **Run workflow** 重新生成；若当前还未合并而没有这个按钮，直接打开本次成功运行下载即可。不要把“下载源码”当成“下载扩展”。合并 PR 后原 Pages 工作流才会部署新增的教务 JSON 导入入口，下载扩展不等于已经更新 iPhone 应用。

安装包包含 `manifest.json`、`popup.html`、`popup.css`、`popup.js`、`capture.js`、`background.js`、`help.html`、`help.css`、`安装和使用.txt`、`BUILD-INFO.json`。构建先清理专用输出目录，验证 ZIP 字节内容与构建目录完全一致，避免混入旧文件或私人文件。不要删除安装后的扩展文件夹。

## 权限、隐私和构建（仅供开发者参考）

扩展仅声明 `activeTab` 与 `scripting`，没有 `cookies`、`webRequest`、`debugger`、`storage`、`downloads` 或 `<all_urls>` 权限，没有监听浏览活动的后台程序、content_scripts、主机白名单或远程代码；仅有一个首次安装时打开本地中文指南的 service worker。弹出窗口禁止网络连接。用户主动启动后，注入的读取器包装本页 fetch 与 XHR，保留原请求和响应行为，只检查返回同源 JSON / text/plain 正文，不访问请求头、请求体、密码、Cookie、Token、认证头或 localStorage。

只保存 `kcmc/cdmc/jcs/jc/xqj/xqjmc/zcd/jsxm`；未知字段不跨入扩展弹窗、不进入导出。只在当前页面内存暂存，停止/超时会恢复仍由助手包装的函数并清空课程；不覆盖之后其他脚本安装的新包装。不自动点击、重放、修改任何查询。文件、文本响应及捕获后的课程数据最多 2 MB、2000 条，过大或结构过深时报错，不静默截断。

`npm run helper:build` 将扩展输出到 `work/school-import-helper/`，并打包为 `public/school-import-helper.zip`；`npm run build` 会自动生成下载包，Vite/PWA 将其与应用一并部署和缓存。ZIP 仅包含 10 个固定安装文件、版本来源信息与面向普通用户的中文说明，不包含源码依赖或用户数据。上述构建产物被 Git 忽略。无需更改 GitHub Pages 基础路径、原有数据库键或部署目标。

测试只使用匿名合成响应，覆盖字段过滤、数据限制、节次/星期冲突、混合周次、去重、特殊课程保留、fetch/XHR 读取、停止恢复与跨源排除。浏览器检查不能替代真实学校页面和 Windows 扩展安装验证；获得脱敏样本后可继续校准编码，原始凭据不需要提供。
