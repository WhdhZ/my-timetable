# MyTimetable · 我的课表

面向中国大学生的极简课程表。中文界面，无广告、无登录、无追踪。针对 iPhone Safari 和主屏幕独立窗口设计，同时支持桌面浏览器。

## Windows 用户：直接下载安装，无需编程

1. 登录 GitHub，打开 [Actions → 构建 Windows 浏览器扩展](https://github.com/WhdhZ/my-timetable/actions/workflows/build-helper.yml)。
2. 选择最新的绿色成功运行，页面底部 **Artifacts → MyTimetable-Windows-Helper** 下载 ZIP。不要点 Code → Download ZIP，那是源码。
3. 右键 ZIP → **全部解压**。在 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions` 开启开发者模式，点击 **加载已解压的扩展程序**，选择含 `manifest.json` 的解压文件夹。
4. 首次安装会打开中文指南。在浏览器正常扫码登录学校后，打开自己的课表页，在助手里点“我已登录，开始读取课表”；回到学校页面查询完整学期，再打开助手检查并导出。
5. 把课程 JSON 传到 iPhone，在 MyTimetable 的“教务 JSON”入口预览、修改后确认导入。不要在未核对时替换原课表。

安装文件夹应保留在固定位置；移动或删除会使扩展失效。ZIP 内包含中文安装、使用和排错说明，不含源码依赖或用户数据。产物需登录 GitHub 下载，保留 30 天；工作流合并到 main 后可点击 Run workflow 重新构建。**本节之外的开发命令只面向开发者，普通用户无需执行。**

目前扩展只读取开始后当前主页面收到的同源响应，不能替代学校登录，也不能接管企业微信客户端；登录跳转或刷新后需在课表页重新开始。零课程、无法注入或识别错误会明确提示，且禁用导出。实际学校页面和 Windows 安装仍需实测。

## 本地运行（仅开发者）

需要 Node.js 22.13+ 或 Node.js 24+。

```bash
npm ci
npm run dev
```

访问终端提示地址后的 `/my-timetable/`。验证生产版本：

```bash
npm test
npm run build
npm run preview
```

生产产物位于 `dist/`。Service Worker 在生产构建中启用；开发服务器不用于验证离线启动。首次访问必须联网，后续离线可启动并查看、编辑课程。

## 使用方法

1. 打开“设置”，填写学期开始日期、教学周数和各节课起止时间，点击“保存设置”。开始日期所在的周一到周日为第 1 周；开学前与学期结束后会显示对应状态。
2. 点击“添加课程”，填写名称、教室、教师、星期、起止节次和颜色。周次支持 `1-8,10,12-16`，支持中文逗号；单双周是在所填写周次范围内，按**教学周编号**筛选。已保存的实际周次会在编辑时完整显示。
3. “今日”提供日期选择、前后周切换和“回到今天”；“课表”为默认首页，七列在窄屏完整显示；左右滑动切换教学周，点击周次可直接选择其他教学周，点击课程查看完整详情后编辑。
4. 同星期、节次相交且上课周次相交时判定冲突。添加/编辑会阻止冲突保存；导入的备份允许保留原有冲突，同时标记并提示调整，避免恢复时丢失课程。
5. 初始没有课程，可载入虚构的演示课表。“设置 → 一键清除演示课程”只删除演示课程；自行新增的课程不受影响。演示需要至少 8 个节次。
6. “导出课表”下载包含课程、学期、节次和外观设置的 JSON 文件；“从备份恢复”会在验证通过并确认后替换当前数据。建议恢复前先导出。备份上限 64 MB、2000 项课程（含待确认课程）。
7. 修改周数或节次导致已有课程越界时，会拒绝保存。请先调整受影响课程。

## 优先使用：已登录教务页面的 JSON 本地导入

新增“教务 JSON”入口，可直接选择课程查询响应文件或粘贴响应正文；Windows Chrome / Edge 本地助手可在正常登录后读取当前主页面后续返回的同源课表 JSON，再导出课程文件。MyTimetable 不读取另一个网站的登录状态，不主动请求学校，不收集或保存密码、Cookie、Token。

支持 `kcmc/cdmc/jcs/jc/xqj/xqjmc/zcd/jsxm` 白名单转换，复用原有预览编辑、冲突检查、语义去重、其他／待确认课程和导入恢复点。裸数字 `jc/jcs/zcd` 等未确认编码会保留待核对，不猜测。尚未获得真实脱敏响应，不声称已适配全部学校编码。

Windows：按上方“直接下载安装”步骤下载 GitHub Actions 产物即可，不需要安装开发工具。也可从已更新的应用导入窗口下载同样结构的扩展 ZIP。

传到 iPhone：用你选择的文件传输方式把导出 JSON 放到 iPhone“文件”，在最终使用的 MyTimetable 主屏幕窗口中选择“教务 JSON”预览导入。已在电脑核对好的完整备份则用“从备份恢复”。没有自动云同步。

完整技术路线、安全边界、跨域框架限制、无扩展的 F12 响应正文方法与使用步骤见 [教务 JSON 与 Windows 助手说明](docs/school-import.md)。若学校仅允许企业微信客户端内访问，本助手不能接管该登录，需要学校允许的浏览器入口或课程导出方式；不会提供复制登录凭据的变通方案。

## 北京农学院 PDF 本地导入

入口：课表右上角“导入”或 **设置 → 导入课表 → PDF 识别 → 选择 PDF**。

1. 在学校本科教学系统中导出个人整学期、可复制文字的 PDF，存到 iPhone“文件”。选择该 PDF 后，应用在本机使用 PDF.js 解析，不上传、不保存原 PDF 文件。
2. 预览显示学年学期、候选数量、实际周次、星期节次、教师、教室和识别提示。展开课程可以修改字段、查看此项原文、复制拆分不同安排，也可以取消导入或补充遗漏课程。
3. 核对实际周次并勾选确认，选择“合并”或“替换”。合并按名称、教师、地点、星期、节次、实际周次和类型去重；同一门课程不同教室或时段分别保留，并保持同色。重复导入不会重复创建相同安排。
4. 缺少可靠星期、跨节范围、周次或超出本机节次配置的内容保存在 **其他／待确认课程**。它们不会进入周网格，不会被当成每周上课。可在设置或课表底部进入核对，补齐后安排到网格；也可单独删除。
5. 导入与 JSON 替换之前自动保存一个本机恢复点，可在 **设置 → 恢复导入前的课表** 恢复。新课表和恢复点在同一个 IndexedDB 事务保存，失败不会只替换一半；恢复操作会把当前课表保存为新的恢复点，便于撤销。仅保留最近一次恢复点，重要版本请另行导出 JSON。
6. PDF 中没有准确钟点时沿用现有节次配置，不修改开学日期，不自动创造学校作息。默认时间只是应用初始示例，请按学校最新安排调整。学期周数不足或节次缺少时，可以先保存为待确认课程，再调整设置并重新核对。

支持以下周次（每个逗号分段独立应用单双周）：

| 表达式             | 解析规则                      |
| ------------------ | ----------------------------- |
| `3周,6-19周`       | 第 3 周与第 6 至 19 周        |
| `3-5周(单),6-18周` | 第 3、5 周，以及第 6 至 18 周 |
| `3-17周(单)`       | 第 3 至 17 周中的奇数周       |
| `6-18周(双)`       | 第 6 至 18 周中的偶数周       |
| `14-16周`          | 第 14、15、16 周              |
| `1-2周,7-12周`     | 两段范围的并集                |

解析器根据文本坐标寻找七天表头和节次列，并读取 PDF 矢量表格线确定合并单元格。支持课程名称、教师、周次、教室等字段标签、跨行文本，以及 `课程名★教师@教室` 的打印记号。没有可靠边界时保留原文供核对；不识别的修饰符不会静默改成每周。

**兼容性边界：**当前只有界面参考截图，没有真实北京农学院导出 PDF 用于版式校准。已用匿名合成 PDF 测试完整流程；无法保证所有学校导出模板都能直接准确识别。扫描图片、加密 PDF、纵向/非七列表格或发生变化的版式可能需要手工核对。应用不包含 OCR；无法解析时会明确提示，不应在未核对情况下替换现有课表。支持 PDF 最大 20 MB / 30 页。

PDF.js 使用 legacy 构建、同源 worker、同源中文 CMap/字体/WASM；首次联网缓存完成后，即使第一次打开导入窗口时已经离线，仍可解析。PDF 解析资源约 5.6 MB，首次离线准备需要等待完整缓存；后续更新也需要下载新的离线资源。导入原文保存在用户本机课程数据中，方便回查，并包含在手动 JSON 备份里。

## 第二阶段课表交互

- “课表”默认显示周一到周日，节次轴显示开始与结束钟点；日期和课程放在同一 CSS Grid 中，375–430px 屏幕无需水平滚动。
- 卡片长度对应节次，长文本换行且限制在卡片内，完整文字在课程详情查看。
- “显示非本周”可显示当前空闲位置的其他周课程；有本周课程时优先显示本周安排。
- 重叠课程以冲突组显示，标记课程数量；点击展开所有冲突课程的准确节次和周次。冲突组卡片跨越整个冲突区间，避免窄屏并排挤压到不可阅读。
- “今日”的列表、课程增删改、演示数据、深浅外观、JSON 备份与原 PWA 功能继续保留。

## 扩展数据来源

`src/imports/types.ts` 定义 `TimetableSource` 接口。来源只负责产出 `ImportResult` 候选，解析、去重、预览和持久化彼此分离。未来获得学校正式授权接口后，可以增加来源适配器，复用核对与导入逻辑。

目前没有企业微信自动同步入口，不收集密码、Cookie 或 Token，不绕过学校登录。应用没有调用任何学校接口。

## 当前 JSON 导入验证

新增匿名测试覆盖字段白名单、嵌套响应、明确节次与周次转换、数字编码待确认、缺少时间的特殊课程、重复导入、fetch/XHR 读取、跨源排除、停止恢复和超时清空。生产预览中验证了打包后的读取器对合成学校页响应的处理、PWA 文件/粘贴预览、去重、敏感字段过滤后持久化、390px 布局和离线导入。未在真实学校页面、Windows 安装环境或 iPhone 真机验证。

## 测试与验证

`npm test` 运行现有与新增单元测试，覆盖教学周、混合单双周、坐标表头、表格边界变换、合并行、单格多课程、换行信息、未知格式保留、重复导入、不同周次显示、IndexedDB 持久化和恢复点。

`src/imports/__fixtures__/synthetic-timetable.pdf` 是完全合成且匿名的测试文件，不含真实学生或课表信息。可选运行 `python3 scripts/generate-pdf-fixture.py` 重新生成，需要自行安装 reportlab；正常运行、构建及 npm test 不依赖 Python。

已对生产预览运行 Chromium 浏览器检查：真实 PDF 文件选择与 PDF.js worker 识别、预览确认、重复导入、冲突详情、375/390/430px 无横向溢出且日期列对齐、刷新持久化、断网启动与 PDF 解析、无第三方网络请求。浏览器检查不能替代 iPhone Safari / 主屏幕 PWA 真机测试。

建议上线后在 iPhone Safari 和主屏幕窗口分别测试：首次缓存、飞行模式启动及 PDF 导入、长课程名、左右滑周、JSON 备份恢复。请使用脱敏的学校 PDF 校准实际导出版式，不要提交真实 PDF 或个人备份到 GitHub。

## iPhone 安装与离线

使用 iPhone **Safari** 打开 HTTPS 部署地址，点击“分享 → 添加到主屏幕”。从主屏幕图标进入后，以独立窗口运行。首次联网打开并完成缓存后，断网也能启动和使用；设置页会显示离线资源准备状态。图标提供 180px Apple Touch Icon、192/512px PWA 图标及独立 maskable 图标。

使用底部安全区域和 `viewport-fit=cover`；移动端表单主要输入字号为 16px。支持浅色、深色及跟随系统，支持减少动态效果的系统偏好。

安装入口和数据隔离行为由 iOS 版本决定。请在主屏幕应用内导入需要的备份，不要假定 Safari 与安装后的存储始终共享。首次缓存完成前不能保证离线启动。

## GitHub Pages 自动部署

本仓库目标地址：`https://WhdhZ.github.io/my-timetable/`。

1. 将所有项目文件（含 `package-lock.json` 和 `.github/workflows/deploy.yml`）提交并推送到 GitHub 的 **main** 分支；若使用其他主分支，请同步修改工作流的 `branches`。
2. GitHub 仓库进入 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**。
3. 在 **Actions** 中查看“验证并部署到 GitHub Pages”运行；也可以手动 Run workflow。工作流先执行 `npm ci`、单元测试和生产构建，再上传 `dist/` 并部署。
4. 部署成功后打开上述地址，刷新验证，再添加到主屏幕。

Vite `base`、manifest `id/start_url/scope`、图标路径和 Service Worker 导航回退均使用 `/my-timetable/`。应用不使用路径路由，页面切换不会产生 GitHub Pages 深层 URL 刷新 404。没有自定义域名或服务器要求。

更新时 Service Worker 会提示有新版本，在没有打开课程编辑或导入窗口时可点击“更新”。不会删除 IndexedDB；存储键保持稳定、备份带 `version: 1`。后续升级数据结构应增加迁移逻辑，不得直接清空旧数据。无需访问网络的字体、图片、分析脚本或远程 API。

## 数据与隐私

- 使用 `idb-keyval` 将课程持久化到 IndexedDB（键 `mytimetable-data-v1`），保存成功后才更新界面。
- 应用没有服务器、数据库服务、登录系统或第三方付费服务，不上传课程信息。
- 源代码仅含明确标记的虚构演示，不包含真实用户课程。请勿把导出的个人备份提交到 GitHub。
- 清除网站数据、无痕模式结束、浏览器存储回收、更换域名/设备可能导致数据丢失。请手动备份重要课表，不能把浏览器本地存储视为永久保险箱。
- 本地存储读取失败时不会自动覆盖已有数据；写入失败会提示导出备份。
